## Completion Gate

The current completion gate is owned by the configured Linear gatekeeper surface named above. This local file is a pointer and evidence index; do not complete the `/goal` from this file alone.

For the current gatekeeper, completion requires verified evidence that the full Builder product works as an OpenClaw gateway plugin, not just that isolated runtime slices pass. A user must be able to install the self-contained plugin into an OpenClaw gateway, open the gateway-served Builder UI, understand connection/auth state, build or load a useful workflow, deploy it to the hosting gateway, see the deploy result, refresh/list the published workflow, run it through Lobster, and inspect any run/approval/error state without reading gateway internals.

The delivery path for the gateway integration is a self-contained Lobster Builder OpenClaw plugin installed into the target gateway. Do not treat an OpenClaw core/main PR as the active completion gate unless the configured gatekeeper explicitly records a minimal upstream API gap.

The full-product gate must include:

- plugin-hosted UI setup and auth that is explicit, recoverable, and not dependent on hidden tokens;
- Deploy that calls `lobster.workflow.publish` on the selected or hosting gateway, shows workflow id/revision or actionable failure, and refreshes the published workflow library;
- clear distinction between local-only actions such as Download YAML/Save Project and gateway actions such as Deploy/Test Run;
- Discord/channel target discovery when the gateway exposes it, plus an explicit manual fallback when discovery cannot prove available targets;
- workflow run, approval, resume, cancel, and failure states visible enough for normal user debugging;
- secret hygiene: no gateway bearer tokens, channel secrets, or personal credentials in workflow YAML, exported projects, README examples, or published workflow documents;
- agent-context permission behavior: `lobster` alone does not grant nested OpenClaw tools, while agents with the required tools can run those workflow actions;
- live verification against the development OpenClaw gateway or disposable real gateways, with browser evidence for the product UI path.
